# RULES.md — обязательные правила для ВСЕХ агентов русификации

Прочитай этот файл целиком перед началом любой задачи. Нарушение этих правил уже однажды
ломало приложение (краш редактора, битые пресеты, сломанная логика единиц длины).

## 1. Переводить ТОЛЬКО отображаемый текст

Меняем только то, что видит пользователь. **Категорически запрещено менять:**

- значения, которые сохраняются в проект `.skf` или в `localStorage`/`IndexedDB`
  (например `shape.kind` = `"box"|"gear"|...`, значение шрифта `"Multilanguage"|"Sans"|...`,
  `gearType` = `"spur"|"helical"|"bevel"`, значение единиц `"Metric (Default)"`, пресеты
  `"200 x 200 mm"`, `"5 mm"`, `"Custom"`, размеры сетки `"0.5 mm"` и т.п.);
- строки, по которым в коде идёт сравнение или выбор (`label === "Length"`,
  `list.includes(x)`, `switch(x)`, `startsWith/endsWith`);
- имена файлов, ключи объектов, идентификаторы, enum-значения, ключи localStorage;
- форматы данных (даты, числа, единицы хранения), имена классов/типов.

### Паттерн «перевод только для отображения»

Если у значения есть внутренний (стабильный) вид и его надо показать по-русски — не меняй
значение, а сделай маппинг в display-слой. Пример уже есть в коде:

```ts
// lib/shapeCatalog.ts — value хранится как "Gear", отображается как t(labelKey)
export function shapeKindLabelKey(kind: string): string {
  return SHAPE_KIND_LABEL_KEYS[kind] ?? kind;   // "gear" -> "shapes.gear"
}
// компонент: <option value={asset.kind}>{t(shapeKindLabelKey(asset.kind))}</option>
```

Аналогично для шрифтов (`textFontLabelKey`), единиц (`unitLabelKey`/`scaleLabelKey`).

## 2. Ключи переводов

- namespace — `lowerCamelCase`, один namespace на область (указан в каждой задаче).
- **Сначала проверь `en.json`**: если ключ уже есть — используй его, НЕ дублируй.
- Плейсхолдеры ICU: `{name}`, `{count}`. Для множественного числа в русском используй
  ICU plural: `"{count, plural, one {1 форма} few {# формы} many {# форм} other {# форм}}"`.
- Имена ключей — по смыслу, в стиле существующих (`saveFile`, `dropFilesHere`).

## 3. НЕ редактируй `en.json` / `ru.json` напрямую (кроме задачи 08)

Задачи 02–06 пишут **только новые** ключи в `docs/russification/keys/<id>.json`
в формате:

```json
{
  "namespace": {
    "key": { "en": "English text", "ru": "Русский текст" }
  }
}
```

- Вкладывай только ключи, которых **нет** в `en.json`.
- `en` — исходный английский текст (как в коде), `ru` — корректный русский перевод.
- Задача 08 соберёт всё это в `en.json`/`ru.json`.

## 4. API next-intl v4

- Клиентский компонент (файл с `"use client"`):
  `const t = useTranslations("namespace");` затем `t("key")` или `t("key", { count: 5 })`.
- Без аргумента `useTranslations()` ключ передаётся полный: `t("editor.save")`.
- Провайдер уже есть в `layout.tsx` — ничего не подключай.
- Серверный код (route.ts): `getTranslations`/`getMessages` из `next-intl/server`
  (см. задачу 06, там отдельный подход через Accept-Language).

## 5. Стиль правок

- Минимальные точечные замены: только литералы → `t(...)`.
- Не рефакторить логику, не переставлять код, не менять структуру/имена переменных.
- Не добавлять зависимости, не менять `layout.tsx`, `middleware.ts`, `next.config.ts`
  (кроме явно разрешённого в задаче 01).
- Не оставлять «полуфабрикатов»: каждый `t("...")` должен ссылаться либо на существующий
  ключ в `en.json`, либо на новый ключ из твоего `keys/<id>.json`.

## 6. Обязательная проверка после правок

1. Проверка типов (npm-скрипт может падать из-за ExecutionPolicy PowerShell — используй
   прямой запуск через node):
   ```
   node "node_modules\typescript\bin\tsc" -p "apps/web/tsconfig.json" --noEmit
   ```
   либо `npm run typecheck`.
2. Убедись, что ошибок, введённых твоими правками, нет.
3. Мысленно (или по диффу) проверь: не задеты ли строки-идентификаторы из п.1.
